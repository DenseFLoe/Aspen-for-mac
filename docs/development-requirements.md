# Aspen for Mac 开发要求与实施顺序

制定日期：2026-11-15（北京时间）。本要求依据当前界面开发、原版功能探索和数据库导出成果制定，作为后续开发的顺序与验收依据。阶段完成情况必须用对应提交和验证结果更新，不能以计划代替实现。

开发主线为：**项目可保存 → 数据库可查询 → 输入具备业务含义 → 简单流程可计算 → 扩展复杂模型。** 界面恢复围绕完整使用流程推进。近期交付范围为阶段 0–2，目标是在 Mac 上保存、重新打开项目并检索真实组分；计算能力按后续阶段接入。

## 本轮推进（2026-11-15）

工作分支 `codex/project-database` 已继承最新对象交互与要求；`main` 保持原状态。阶段 0 的集成基线和首批参考场景、阶段 1 保存与撤销实现及检查见 [项目保存记录](project-persistence.md)。用户确认旧 UI 外壳在 Mac 初步使用时基本有响应；本轮新功能的 Mac 实机验收仍待执行。保存 `127fd28`、数据库 `a389c41`、保存修复 `7c68541`、打包修复 `eefc17f` 均已上传。阶段 0–2 的代码实现及 Windows／macOS 自动检查通过，最终 [macOS Actions](https://github.com/DenseFLoe/Aspen-for-mac/actions/runs/43686255862) 包含包内插件与保存自检。运行数据和边界见 [只读数据库接入](runtime-property-database.md)；Mac 本轮实机验收仍未完成，不把自动构建标为实机通过。

## 开发顺序与阶段验收

下表为交付顺序。可提前开展后续阶段所需的只读调查、参考案例采集和技术可行性验证；依赖的数据结构、字段含义或计算能力未验收时，不得将依赖它们的功能标为完成。

| 阶段 | 开发内容 | 验收标准 |
| --- | --- | --- |
| **0 统一开发基线** | 验证并整合最新对象交互成果，更新分支与功能记录，选定首批参考案例 | 整合后的代码包含已验证的静态恢复与对象交互功能；Windows 和 macOS 对应检查通过；明确已实现、待核实和未实现范围 |
| **1 项目模型与保存** | 建立独立于页面控件的项目模型；保存组分、方法、对象、父子关系、输入、全局单位和流程图连线；实现打开、保存、另存为、未保存提示及基础撤销重做 | 关闭程序后重新打开，输入、对象身份、父子关系和连线完整恢复；复制后输入独立，删除与撤销不会留下失效引用；保存失败保留原文件 |
| **2 只读物性数据库** | 在新目录生成运行用数据库；按名称、CAS 和别名检索；将选中组分加入项目；展示数据库、子库、来源、单位及参数 | 查询结果可追溯到原记录；组分可加入、移除并随项目保存；库缺失或版本不符时给出明确提示；原始导出和归档不变 |
| **3 核心字段与单位** | 优先实现设置、组分、物性方法、物料流股及首批模块的字段绑定、候选项、必填项、条件显隐和单位换算 | 每个接入字段具有明确类型、单位和对象引用；切换单位保持同一物理量；非法值和缺失输入可定位到具体字段；未核实候选项不冒充已验证选项 |
| **4 流程图连接规则** | 实现端口、方向、物料／热量／功连接约束，完善断开、重连、删除联动和必要模块图形 | 小流程连接关系可验证、可保存、可恢复；不兼容连接被阻止并说明原因；移动图形不改变拓扑；复杂布线和图形精修后续扩展 |
| **5 最小物性与闪蒸能力** | 确定跨平台计算实现路线；从少数组分和一种明确支持的物性方法起步，验证必要物性及 TP／PH 闪蒸 | 独立数值检查和原版参考案例均达到预先记录的容差；说明适用范围、单位、参数来源和焓基准；缺失参数、超范围及不收敛有明确失败结果 |
| **6 简单流程计算** | 按 Mixer、分流器、Heater、Flash2 顺序接入；实现无循环流程的计算顺序、结果表、日志和输入修改后的结果失效机制 | “进料 → 混合 → 加热 → 闪蒸 → 结果”完整运行，物料和能量衡算达到规定容差；保存后可复算；失败时不展示旧结果为当前成功结果 |
| **7 循环与分析** | 先实现循环物流收敛和初始化，再实现设计规定、灵敏度分析，随后实现优化 | 单次流程计算已通过验收；循环与重复计算可复现；提供停止条件、迭代记录和失败诊断；分析任务不会意外覆盖基准案例 |
| **8 复杂模型与兼容** | 按实际案例需求扩展 RadFrac、反应器、复杂换热器，再推进电解质、石油、聚合物等；逐步研究原版案例文件导入导出 | 每个新增模型具备完整输入、计算、结果和参考案例；文件兼容逐项声明支持范围，遇到不支持的数据不得静默丢弃 |

阶段 1 的项目格式先保证自身数据完整保存和版本可识别，不以兼容原版案例格式为前提。阶段 5 的计算路线需要验证 Mac 可用性、数值正确性和集成成本；Windows 原装数据读取接口的存在不代表已经具备 Mac 计算引擎。

## 项目模型与字段约束

1. 对象使用稳定标识建立关系，显示名称可以修改。页面控件负责编辑和展示，项目模型负责持有业务数据；保存和求解均从项目模型读取。
2. 区分业务输入、界面显示状态和计算结果。输入至少表达数值、单位或量纲、是否已指定及必要的对象引用；不得把空值、缺失值和数值零混为一类。
3. 保留尚未接入语义的会话输入，明确其未验证状态，避免迁移到项目模型时丢失现有输入。按首批案例逐页接入，不以一次性恢复全部变量绑定作为前置条件。
4. 项目文件包含格式版本和数据依赖标识。写入应使用临时文件及成功后的替换机制；读取失败不得破坏当前项目，未来格式迁移需保留可恢复的原文件。
5. 基础撤销重做至少覆盖对象创建、重命名、删除、输入修改和图形移动；新增连接编辑功能时同步纳入撤销范围。界面、导航、对象列表和模型状态必须一致。

## 数据接入与永久保留

[数据库永久保留原则](database-preservation.md) 和 [AGENTS.md](../AGENTS.md) 对所有阶段持续生效。受保护的原始导出、归档、校验记录和保留声明不得因开发、恢复、构建或清理而删除、覆盖或损坏。

- 运行用数据库、索引及迁移结果一律写入新的本地路径；应用只读访问已发布的数据版本。运行数据与原始资产分离，数据库内容及归档不加入 Git、不上传 GitHub。
- 参数身份保留数据库、子库、组分实体、物性与元素顺序；不得仅按显示名称合并记录。查询展示与可用于计算的参数分别标明验证状态。
- 原始 `value_text` 十进制字符串、单位、来源和关系元数据完整保留。数值预览、API 数组或转换后的计算值不得覆盖原始表示。
- 当前有 52,611 条 API 数组表示差异需要按物性类别解释。先验证首批计算需要的参数子集；组分检索无需等待全部差异解决。未解释的差异不得自动修正、补零或直接投入计算。
- 旧二进制文件的可逆保存不代表其语义已解析。具体边界沿用 [明文导出说明](plaintext-database-export.md)，不把数据覆盖核验视为公式或求解器正确性证明。

## 原版探索与参考案例

优先沿“组分检索 → 方法选择 → 流股输入 → Mixer／Heater／Flash2 → 运行与结果”观察原版。每个待实现功能记录前置案例、操作步骤、默认值、必填条件、联动候选项、单位、错误提示和输出含义；取消路径与成功路径分别核实。

每条观察链形成可复用的验收案例，注明原版版本、组分、物性方法、输入与单位、参考输出、容差和证据位置。计算功能同时采用独立检查和原版对照；参考结果必须附带方法、条件和基准，不能只比较画面上的数字。

功能完成度按完整使用流程记录，区分“静态布局存在”“本地交互通过”“原版行为已核实”“业务或计算已验证”。创建 67 种模块并打开输入页，只能证明相应对象与页面链可用。缺失的 11 个布局引用及其他未知动态行为按首批案例的实际依赖排序处理。

## Mac 验证与里程碑交付

- 每个涉及应用代码的里程碑保留适当的 Windows 构建与测试、macOS Actions，并记录具体提交和检查结果。资源解析、数据读取、项目往返保存、单位换算、拓扑和数值算法分别使用适合其行为的检查。
- 从近期阶段开始验证 Mac 实机的打开、编辑、保存、重开、文件选择及数据库路径处理，同时检查应用包的 Qt 运行依赖。自动化未覆盖的实机行为保持待验证状态。
- 正式分发阶段再完成签名、公证及安装体验验证。持续构建成功、应用包可运行和正式发布是分别验收的事项。
- 每个有意义且已验证的里程碑单独提交并及时上传工作分支，报告提交 SHA、检查及上传结果。合入 main 前按仓库流程核对历史和用户改动；本开发顺序不改变现有分支权限规则。
- 同步更新功能记录和本要求中的阶段状态；未完成验收的功能不得因页面、按钮或对象入口存在而标记完成。
