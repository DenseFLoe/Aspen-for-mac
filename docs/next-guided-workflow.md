# 以“下一步”为主线的流程研究与实走

后续实施：字段、单位和数据驱动引导见 [Flash2 输入与引导](flash2-input-guidance.md)，端口及汽液角色检查见 [Flash2 连接规则](flash2-topology.md)。本文的移植缺口描述保留为研究时基准，不代表后续代码状态。

日期：2026-11-17（北京时间）。代码基准：`main@74eae60`；研究分支：`codex/next-guided-workflow`。

本轮在原版 Aspen Plus V15 中完成了一个真实 Flash2 案例的输入、运行和结果查看。成功案例使用安装自带入门模板的组分、方法、参数和连线，再由本轮手动填写设备及进料条件，通过“下一步”触发计算。**这证明原版参考流程已经走通；移植版的引导与计算尚未实现。**

## 结论与移植版缺口

“下一步”根据当前编辑上下文、项目缺项与运行状态决定行为。它既会留在本页解释缺项，也会跳到其他对象、切换环境、提出运行确认，或引导查看结果。不要实现成固定的“组分→方法→流股→设备”页面轮播；当前页面、已有输入和可用结果都会改变路径。

移植版基准中的 `UiShellActions.cpp` 对 `action == "next"` 仅调用 `dispatch("component:specifications")` 并显示固定文字，没有读取完成状态。`quick-next` 映射到同一动作；状态栏“检查状态”也借用了该动作。`Incomplete` 标签为固定文字，运行按钮在目录中禁用，控制面板没有计算记录。因此目前在移植版无法用这个按钮走完相同流程。界面可打开和保存测试通过，均不能作为此操作链的验收。

执行顺序沿用三轮[按钮分析](../analysis/button-logic-20261116/report.md)，本轮重点复核了以下边界：

1. `StoreValueEvent` 提交待决编辑，先于 `ApwnFormContentHost.NextHit`。
2. 当前表单尚有缺项时，留在表单/页签内处理；不强行向后翻页。
3. 当前表单完成后，通过 `Custom Actions / Next Incomplete` 查询项目模型。普通路径指向下一不完整节点；流程图路径提示完成连接；`GOTOSIM` 切换环境；`RUN` 进入控制面板与运行链；`CANCEL` 中止。
4. `NextStatus` 继续处理输入完整、运行中、运行失败、成功/警告/错误结果等状态。项目查询、表单提示和运行状态共同决定最终表现。

`Next Incomplete` 原生处理函数、完整 CC Nodes 真值表以及所有状态码仍未解析。本轮成功案例补充了动态证据，不能覆盖全部令牌和异常分支。

## 实走二：甲醇/水 Flash2 的完整参考流程

为继续验证后半段，复制安装文件 `GUI/Examples/Getting Started/Process/flash.bkp` 到新的本地研究目录。起始文件 SHA-256：`5fd521dea396260192cc23710f07757c8ba9f7bbdd511bf8492fefd10fe4b3c8`，副本与安装源一致。原文件未改动。

模板预置 METHANOL、WATER、NRTL 与参数，以及 `1 → B1(Flash2) → 2(汽相)、3(液相)` 的拓扑；设备温压和进料条件未填写。本轮在原版界面实际输入：

| 对象 | 规定 |
| --- | --- |
| 全局 | ENG，NRTL，METHANOL/WATER |
| 进料 1 | 温度 200 °F，压力 50 psia，总摩尔流量 100 lbmol/hr；两组分摩尔分率各 0.5 |
| B1 | 温度＋压力规定：185 °F、14.7 psia |

操作链和状态见可机读[参考案例](../analysis/next-guidance-20261117/case.json)：

1. 在 B1 点“下一步”，缺温度与压力时逐项提示对应规定；填写并完成提交后，页面和树节点转为完成。
2. 再点“下一步”，跳到进料 1 的输入页。
3. 空进料点“下一步”，先提示必须指定组分流量、分率或浓度。将组成基准切为摩尔分率后，组成单位框禁用；本例另行输入总流量。
4. 输入两组分分率、进料温压和总流量，提交编辑后，状态栏显示“所需输入完整”。
5. 点“下一步”，出现“要求的输入已完成”，询问是否立即运行模拟。确认后打开控制面板并运行 B1。
6. 控制面板显示计算完成，输入翻译和模拟均无错误/警告；实际引擎历史记录含 B1 的 FLASH2 计算与 `Results generated`。
7. 计算后再点“下一步”，出现“模拟完成”，默认选项指向运行状态结果表。确认后打开该结果页。
8. 打开流股摘要，观察到进料为 200 °F、50 psia；两条产品为 185 °F、14.7 psia；2 为汽相、3 为液相。

输入提交期间曾出现字段已显示新数值、完成图标随后更新，但本次“下一步”仍弹出先前缺项消息的过渡现象。关闭提示、确认编辑提交及完成状态刷新后，后续导航成功。本轮未隔离其原因，不能断言是原版缺陷或移植时必须模仿的行为。自动验收应等待模型完成状态，避免只判断输入框文字。

结果页之后的截图捕获发生 `IGraphicsCaptureItemInterop.CreateForMonitor 0x80070057`；重新绑定窗口后仍失败，因此未继续抓取完整流量/组成结果表，也没有通过 GUI 另存完成版 `.apw`。成功运行的输入、自动备份、历史和二进制结果已在文件系统独立复制保留。

## 后续实现与验收主线

下一次实现以这条参考流程建立独立于控件的完成状态：`需要输入 / 输入完整 / 正在计算 / 成功 / 有警告 / 失败 / 输入修改后结果失效`。每个缺项带稳定对象身份、字段身份、原因和导航目标。

先完成组分、方法、该进料与 Flash2 规定的真实字段/单位和连接校验；“下一步”提交当前编辑，再查询缺项并定位。输入完整后明确显示计算支持范围；计算尚未接入时保持未实现状态，不能用占位结果假装运行成功。随后按开发要求接入必要物性与闪蒸，最后补齐运行/失败/结果/结果失效引导。

验收应复用同一案例改变数据：缺组分、缺方法、缺设备规定、缺进料组成、输入完整、成功结果，以及修改输入后的旧结果失效。当前研究没有把这些移植功能标为完成，也没有扩展到全设备和全页面穷举。
