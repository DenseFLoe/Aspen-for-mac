# 85 件未成功原件补逆向

每个聊天固定处理一个原件。按[旧逐件规则](../../docs/reverse-execution-workflow.md)完成逆向、静态验收和归档。静态通过以[验收要求](../../docs/static-acceptance.md)为准。

## 输入和工具

1. 从[原件索引](原件索引.csv)查这一件的路径、SHA-256 和旧报告。原件在[原版文件](../../原版文件/)目录。85 个原件复用自原交接分支的固定提交 `ad53650f6071f83b133ede7bf847bc5096cd3b56`。56 个大文件沿用原 Git LFS 存储。
2. 只下载本件，先核对指纹再开始。用 [原件下载脚本](../../tools/fetch_reverse_original.ps1)传入本分支的固定准备提交、原件路径、SHA-256 和该件的输入目录。LFS 原件加上 `-LargeFile`。
3. 按格式选工具。托管代码用 ILSpy 和 IL 对照，原生代码用本机 Ghidra，库文件按成员处理。工具、依赖和原件均按 [AGENTS.md](../../AGENTS.md) 的项目要求取用。

## 收录成果

- 每个聊天使用自己的原件指纹目录。局部结果、工具工程、临时文件和其他支撑材料从本件目录读取。
- 通过验收的原件将源码、必要资源、逐件说明和证据归到 `reverse/01-completed/<轮次>/<产品>/<原路径>`。局部或未通过成果归到 `reverse/02-incomplete/<轮次>/<产品>/<原路径>`。说明要能对应原件和成果指纹，解释差异、缺口及继续条件。
- 由本批协调聊天核验逐件交付，集中在工作分支提交。通过件合入主干时，同步移动原件状态目录并更新逐件总表及索引。保护资产和本地临时物按项目规则处理。
