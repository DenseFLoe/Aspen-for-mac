# 规划请求：native PE 链（Ghidra 全函数反汇编 + 全函数伪 C）

## 1. 要你产出什么

一份**可执行的计划 + 任务书**：把 `等待铁头猫/` 下 **19 个 native PE**（清单 `read-test-waiting.csv` 里 `kind=native`，sha256 去重后 19 件）逐件做成
(a) Ghidra 12.1.4 **全函数反汇编清单**（含导入日志：语言/基址/内存块，逐函数地址 + 函数名 + 指令）
(b) Ghidra Decompiler **全函数伪 C**（逐函数，带地址与函数名；反编译失败的函数要显式标 `// DECOMP-FAIL <addr> <reason>`，不许静默跳过）
并给出上传到 `codex/20261120-batch-review` 分支的产物布局与逐件 commit 方案。

## 2. 我方已有的约束（不可改动，只在此基础上规划）

- **判据（native 半边，来自我方 00-req §9 D2/D4/D5）**：
  - D2：19 件每件都有 asm + 伪 C，**函数数 > 0**；`FUNC 数 == // FUNC 数 + // DECOMP-FAIL 数`（恒等式，不得凑数）。
  - D4：远端读回每件目录两类产物齐全；`INDEX.md` 行数 = 参与件数（native 19）。
  - D5：不碰 main（before/after main sha 必须相同）；只推 `codex/20261120-batch-review`；**原件不上传**（`dl/**` 只在本地读）。
- **体积**：单文件 ≤5 MB 明文；超出用 `gzip -9` 存 `.txt.gz`，同名 `.md` 写解压命令。
- **隐私**：产物内不得出现本机绝对路径 / 用户名 / 凭据；Ghidra 输出的路径字段必须脱敏（可用相对路径或占位符）。
- **提交**：逐件 commit，message 带 `round=20261120`、件名、产物类型；**禁止 force-push**；**禁止任何写 `refs/heads/main` 的请求**。
- **无人值守**：单件失败不得中断整批 —— 记 `status=failed_analyze` + 原因，继续下一件；末行汇总 `NATIVE done=… failed=…`。
- **工具口径**：本机执行面是 ptc 子档，只有 `run_code` 能直呼，其余工具在 `run_code` 里调 `tools.read`/`tools.write`/`tools.ops_bash`。任务书别写"用 read/write 工具"。
