# thesso.dll 静态验收（二组第 3 轮）

判定为**静态验收未通过**。修复后交由二组复验。

## 原件与核验方法

- 原件为 Aspen Plus V15 的 `[CommonFiles64Folder]/Hyprotech/COMThermo/thesso.dll`，产品版本 `35.0.0.1`，大小 658,368 字节。安装包来源清单记录 `thesso~1.cab` 的成员 `thesso.dll.4DECC2B6_E814_11D5_810C_00D0B7E12D58`。对复用的提取件实算 SHA-256，结果为 `02c1138db51e927cf002a7d720767d4d306332e4faa612270d226c641a8c85c6`。
- 用 Python 和 pefile 2024.8.26 读取原件的 PE 头、节、导入导出、异常目录、资源目录和指定 RVA 的原始指令。原件为 x64 PE32+，CLR 目录为空，镜像基址为 `0x180000000`，入口 RVA 为 `0x15AF0`。四个导出为 `DllCanUnloadNow`（`0x13EE0`）、`DllGetClassObject`（`0x13EF0`）、`DllRegisterServer`（`0x13FC0`）、`DllUnregisterServer`（`0x14220`）。导入模块为 KERNEL32、USER32、ADVAPI32、OLE32 和 OLEAUT32。
- 从 W2 第 3 卷流式提取两份正式导出，逐份核对 SHA-256、大小和远端 Git blob。成员清单中的阶段版与正式版对应指纹一致。按 [IDA 9.5 / Hex-Rays 导出](v0.20261121-w2/)的 `FUNC` 地址计数，伪 C 和反汇编各有 3,589 个不同入口，地址集合一致，覆盖 PE 入口和四个导出。原异常目录的 2,126 个不同起始 RVA 中，2,123 个出现在反汇编指令地址中。余下 `0x25C50`、`0x26330`、`0x26600` 需对照原代码与异常区间核对归属。

## 可复查的缺口

1. 伪 C 第 78796 至 78803 行的 VA `0x180051FCC` 在受检查的首字节为零时只留下 `JUMPOUT(0x180051FD1)`。反汇编第 90681 至 90684 行在条件跳转后结束。按 PE RVA `0x51FCC` 读取 11 字节得到 `80 3a 00 75 06 b8 01 00 00 00 c3`。零值路径沿顺序执行，在 RVA `0x51FD1` 处执行 `mov eax, 1` 和 `ret`。正式导出缺少该返回分支的实现。伪 C 还有 9 处其他 `JUMPOUT` 和 12 处局部变量分配警告，应按原指令逐项核对。
2. 原件 `.rsrc` 有 9 个叶节点。COM 相关资源为 `REGISTRY/101–105/1033` 的 5 份注册脚本及 `TYPELIB/1/1033`（RVA `0xA22E0`，3,264 字节，签名 `MSFT`）。另外三项为字符串表 `6/7/1033`、版本资源 `16/1/1033` 和清单 `24/2/1033`。两份正式导出仅包含按函数生成的文本。可以查到 `DllRegisterServer`、`LoadTypeLib` 和 `FindResourceA`，归档缺少注册脚本、类型库定义及其余资源的对应交付。

## 修复与复验

补齐原字节确认的返回分支和缺失指令，对照异常区间核对其余控制流与栈变量。补充注册脚本、类型库和相关资源的可编辑表示与逐项对应证据。Windows 重建阶段另验 COM 注册和运行行为。
