# thflash.dll 静态验收（二组第 2 轮）

判定为**静态验收未通过**。修复后交由二组复验。

## 原件与核验方法

- 原件为 Aspen Plus V15 的 `[CommonFiles64Folder]/Hyprotech/COMThermo/thflash.dll`，版本 `35.0.0.1`，大小 1,482,176 字节。安装包来源清单记录 `thflas~1.cab` 的成员 `thflash.dll.4DECC2B6_E814_11D5_810C_00D0B7E12D58`。复用已提取成员，SHA-256 为 `01cf07268dcc5f88a5dd46bec478902259ecbe88b5b0781079b6e759973e9278`。
- 用 Python 和 pefile 2024.8.26 读取 PE 头、节、导入导出、异常目录和资源目录。原件为 x64 PE32+，CLR 目录为空，镜像基址为 `0x180000000`，入口 RVA 为 `0xA6670`，有四个 COM 导出 `DllCanUnloadNow`、`DllGetClassObject`、`DllRegisterServer`、`DllUnregisterServer`。导入模块为 KERNEL32、USER32、ADVAPI32、OLE32 和 OLEAUT32。
- 从 W2 发布包第 5 卷提取 [IDA 9.5 / Hex-Rays 报告所列导出](v0.20261121-w2/)。四份文本的 SHA-256 和 Git blob 分别与发布包清单和远端对象吻合。正式与阶段版逐行比对，C 和反汇编各有一行差异，均涉及日志路径的脱敏。
- 正式伪 C 和反汇编各有 5,639 个不同的 `FUNC` 入口，地址集合一致，覆盖 PE 入口和四个导出。异常目录的 3,742 个不同起始 RVA 有 3,739 个出现在反汇编指令地址中。未出现的三个 RVA 为 `0xB6930`、`0xB7190`、`0xB7820`，须核对函数片段和异常区间。异常目录可以指向函数片段，覆盖检查应使用实际指令地址。

## 可复查的缺口

1. 正式伪 C 第 193397 至 193406 行对应 VA `0x1800E2958`。被检查的首字节为零时只留下 `JUMPOUT(0x1800E295D)`。正式反汇编第 232279 至 232282 行在条件跳转后结束。按 PE RVA `0xE2958` 读取 11 字节，得到 `80 3a 00 75 06 b8 01 00 00 00 c3`。其中 RVA `0xE295D` 处顺序执行 `mov eax, 1` 和 `ret`，所以该输入在原函数返回 1。两份伪 C 均缺少这个返回分支。正式版还出现 9 处其他 `JUMPOUT` 和 14 处局部变量分配警告。复验时应逐一核对实际控制流和栈变量。
2. 四份导出只含函数伪 C 或逐函数反汇编，缺少原件的 COM 注册脚本和类型库可编辑定义。原 `.rsrc` 有 27 个资源叶节点，包括 `REGISTRY/101–123/1033` 的 23 项以及 `TYPELIB/1/1033`（RVA `0x164588`，25,220 字节，签名 `MSFT`）。其他三项为字符串表 `6/7/1033`、版本资源 `16/1/1033`、清单 `24/2/1033`。导出中可查到 `DllRegisterServer`、`LoadTypeLib` 和 `FindResourceA`／`LoadResource`，仍缺这些资源本身的对应材料。

## 修复与复验

按原 PE 补齐函数块和数据引用，还原条件返回并核对其余跳转及异常区间。补充注册脚本、类型库及相关资源的可编辑表示和逐项对应证据。Windows 重建后另验 COM 注册与运行行为。
