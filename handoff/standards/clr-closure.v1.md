# CLR 引用闭包与配对构建 v1

1. 公布产品目录、全库边界、枚举方式和准确分母。读取 PE/CLI 元数据中的 AssemblyDef 与 AssemblyRef，不执行原件。记录逐行引用者和引用标识（名称、版本、文化、公钥标记），同名不同身份分开。
2. 逐条按引用者同目录、同产品目录、全库查找。只接受身份匹配的文件；同优先级、同身份而内容不同且无法消歧时保留歧义。逐件给出传递闭包和全部未解析名称，说明框架引用与产品库的关系。直接边、传递节点、物理文件和唯一原件分别计数，并明确统计范围。
3. 至少三件不同原件，至少一件大于 1 MiB。每件使用相同原件、相同反编译源码、SDK、目标框架、语言版本、签名和资源处理，干净构建两次。唯一实验变量为闭包 Reference。保留指纹、复跑命令、各次退出码、实际错误数和诊断。任何为适配测试编译所作改动均须记录。
4. 交付 assemblyrefs.csv、closure.json、closure-test.md 和复跑入口。报告至少两种路径的代价、已知缺失的程序集或非引用输入，以及可确定的判断边界。构建成功只覆盖固定输入及环境下的编译门槛。把未解析引用、环境问题和剩余编译错误分别列明。
