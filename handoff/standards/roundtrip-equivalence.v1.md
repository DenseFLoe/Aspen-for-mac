# CLR 回环 v1

采用 C + A。C 核对 #372 所定义的类型与方法签名投影，包括仅原件/仅重编两侧计数。A 覆盖配对的方法清单、外部成员与指令数，逐件列缺失、多出的方法和未解释差异。两项都要交；差异经原件证据解释后才可裁定。方法体的常量、分支、异常处理或资源仍按静态验收 v2 核对，即使两项计数都相等。C 的原始 9/9 不能推得整批已通过。

| 差异 | 白名单裁定 | 适用证据 |
| --- | --- | --- |
| 1. 状态机 `d__0/d__6` | 同意仅归一生成编号 | 同一宿主方法、同一生成类型，成员一一对应，保留泛型元数与引用关系 |
| 2. 迭代器 `__wrap2/__wrap1` | 同意仅归一生成编号 | 对应字段类型、用途、finally 嵌套与清理顺序一致，映射一一对应 |
| 3. 字符串 switch 哈希与长度/字符派发 | 否决自动豁免 | 移除白名单；逐方法核对全部字符串、目标分支、null/default 和碰撞路径 |
| 4. 数组逐项写入与 InitializeArray | 否决自动豁免 | 移除白名单；按元素类型、长度、顺序及 RVA 中实际值核对，保留初始化时机与可观察写入 |
| 5. 当前托管线程 ID 的两种 API | 同意等价替换 | 确认为目标框架可用的系统 API、取当前线程、同一读取位置；替换以外的控制流和调用另核 |

只对提案记录的编译环境使用上述白名单。工具链或目标框架改变时重新审查。保留原始计数、每一处差异的类别与证据、新口径下白名单调整后计数和逐件未决项。无逐方法记录时登记缺证，不补推通过率。

## 本轮重报

输入固定为 #372 的同一批 9 件。使用既有逐方法明细生成 `inbox/ROUNDTRIP-9/methods.csv`，每行一个唯一的（sample, method）对。列为 `sample,method,raw,rule,evidence`，raw 取 `equal` 或 `different`；rule 取 1–5 或空，evidence 对差异填可定位的原件/重编方法或 IL 记录。多种差异同现时 rule 留空并在 evidence 列逐项写明，保守记为待核。校验命令核对既有样本和计数、重算原始/按白名单调整/待核三列。补交明细后由上游核查证据和裁定。
