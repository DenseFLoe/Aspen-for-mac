## 六组动态长度

六组均读取 64 位计数，以有符号比较跳过 `count <= 0`。`1..12` 由内联的 8 字节步进处理。`count >= 13` 将 `R8` 设为 `count * 8` 的低 64 位后调用复制或填充。源代码中的 `qword` 和 `movsd` 只证明 8 字节单位。只有 `0x71cc` 旁的 `movsd` 和 `DMS_LENTHM` 分列输出支持其中一个实数工作区路径，仍需声明确认存储类型。切换点的第一批长度为 104 字节。完整无符号乘积要求 `count <= 0x1fffffffffffffff`，要求字节数同时可表示为非负有符号 64 位时为 `count <= 0x0fffffffffffffff`。两个数值为算术上限。原件乘八前的局部路径未比较这两个上限，真实区间还取决于各工作区的声明和生产者。

配套 `DMS_LENTHM @ 0x204d0` 保存第二参数到 RDI、第三参数到 RSI。其查找例程 `0xb570` 补入记录值。若 `0x1282e8 == -1` 且配套状态非零，外部后端 `Lenthi`、`Lenthr` 的返回分别写到第二、第三参数。常规路径以 `B = [DMS_DMS+8]`、`I = [0x1282e8]`、`L = [0x1282d8]`、`U = [0x128300]` 表示。当 `mode = [0x1282e0]` 非零时，输出为 `B*I-L` 和 `trunc(U/B) - (mode == 1 ? 0 : I)`，除法保留原件的 32/64 位分流。`mode == 0` 时输出 `U-L` 和 `0`。仍需 DMS 查找记录及备用后端的允许形状，方能证实两个输出的全路径上限。

`DMS_TINFO+0x848` 的七个配套库引用来自 `.pdata` 所覆盖范围内可解码的 RIP 引用。`0x4074` 是其中一处八字节初始化写入。其他指令包括取地址如 `0x1eb51 → 0x63cf0` 及 `0x3b3c9 → 0xcc80`，需核实这些引用与导出字段的外部写入者，才能把初始化长度当作持续不变量。
