# DMS_TINFO+0x848 在两条配套路径上的传递

本轮核对的两个固定原件和指令字节见 [机器证据](evidence.json)。atdms.dll 的 DMS_TINFO 导出在 `0x964c0`，字段 `0x96d08` 在可写的零填充区。DMS_APOPEN 在 `0x4074` 写 QWORD 64。对 .pdata 所覆盖的原件区间扫描，仍得到七处直接 RIP 相对引用。

- `0x1eb51 → 0x1eb73 → 0x63cf0`：DMS_ITSUM 用 RCX 传 `&DMS_TINFO[+0x848]`，第 5 参数是 256。DMS_INT2CS 在 `0x63cff` 读取 QWORD 后变成数值计数，按每个 8 字节元素取前四个字节。它写入 R9 所指缓冲区 `0x11d920`，按需要用 `0x20` 填充，在 R8 所指 `0x11da20` 写回有效字符数。该调用点的三个地址不同，沿已证实路径未向外层传递计数字段地址。
- `0x3b3c9 → 0x3b3d7 → 0xcc80`：DMS_CPLNKI 将 RDX 保存到 R14。在 `0xcd30` 读取 QWORD 后左移两位，传指向栈副本的地址到 `0x63e00`。另在 `0xcd89/0xcd92` 将原地址转传到 `0x5be70`，该函数在 `0x5be9a` 只取低 DWORD，其独立输出指针来自调用者第七参数。原地址也在两个分支经 `0xcdd5`、`0xd20d` 交给 DMS_INT2CS 的第一个参数。对应输出缓冲区为 `0xa33a8`，返回长度在 R8 指向的独立槽。已跟踪的调用形参均作为长度输入。
- 其余显式取址也已定位。`0x15fde` 与 `0x37e31` 经 R9 传入 `0x3aed0` 后保存在 R15，在 `0x3b2f8`、`0x3b489` 传给两条读取路径。`0x16278` 在 `0x162fb` 将地址交给 `0x61660`，后者在 `0x6169f` 取低 DWORD。已核范围内唯一直接写为 `0x4074`。

| ppexec 调用 RVA | 初始化路径的目的范围（相对符号） | 字节 |
| --- | --- | --- |
| `0x7e5a` | DMS_TINFO `[0x2f0, 0x4f0)` | 512 |
| `0x7e70` | DMS_TINFO `[0x4f8, 0x6f8)` | 512 |
| `0x7e86` | DMS_TINFO `[0xf0, 0x2f0)` | 512 |
| `0x79fa` | DMS_PGMNFO `[0x18, 0x218)`，填 `0x20` | 512 |

三个复制目的区在本初始化路径互不重叠。原件在调用前取有符号 QWORD，正数达到 13 项时进入批量路径。已证实 64 项时通过 104、112、120 字节分支的前置条件不成立。DMS_TINFO 可由外部消费者按导出地址寻址，其他按基址寻址的写入及实际声明尚未穷尽。三处 DMS_PLEX 源项容量、PGMNFO 目的字段声明和其余动态生产者仍待核实，五处内部分派继续按原判据保持未决。
