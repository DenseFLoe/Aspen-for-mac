# ppexec.dll 的复制、填充分派索引

检查对象是任务 NATIVE-346 第九号分配指定的 ppexec.dll，SHA-256 为 `d93227b9a8f77c09fc1294834b6a4d87ba03a0697a680039fdce35cb1ce4549a`。长度单位为字节。下列结果适用于六个复制或填充例程的标准入口；输入为可由例程内有符号比较表示的非负长度。五处还需要确认调用方声明的长度契约。

| 待核分派 RVA | 正常路径的索引（含端点） | 原件上的范围依据或恢复条件 |
|---|---|---|
| 0x91a4、0xe215 | 各 0–255 | 尾段按 256 字节处理。需要补调用方长度声明。 |
| 0xa6e4、0xf135 | 各 0–127 | 入口按 128 字节分流。需要补调用方长度声明。 |
| 0x12c93 | 0–8 | 入口按 1 和 8 字节分流，其中 1 字节另有直接返回。需要补调用方长度声明。 |
| 0xaa51、0xf2aa | 各 0–511 | 64 字节对齐前缀和 512 字节主循环后的尾段。 |
| 0x12cc3 | 2–176 | 先有 8 字节分流，可扣除至多 7 个对齐字节，随后以 176 为上界。 |
| 0x135c3 | 已知入口未到达 | 指令块 `[0x135a4, 0x135c7)` 前是无条件分派。重读全代码、原件入口、重定位和分派表，未发现指向块内的静态引用。代码字节仍保留。 |
| 0x13a89 | 0–31 | 32 字节循环的尾部，包含全部 15 条对齐支路。 |
| 0x13af3 | 0–3 | 64 字节循环退出时余数在 0–63，除以 16 后仅选 4 个槽。表中索引 9 的空槽不在此范围。 |

附核 0x1403f，其对齐索引受 `and r10, 0xf` 限制在 0–15，排除了第二个空槽（索引 17）。本次 20 个待核位置以第五轮 `control-gaps.csv` 为基数；0x1403f 是沿用并复核的支撑证据。

脚本读取第五轮固定清单，逐个校验 532 个代码范围的原件字节指纹，并在原件核对 34 条分派指令、20 张表中全部 2,946 个槽。分析从每个例程入口沿直接跳转、比较分支、分派槽和顺序指令传播剩余长度区间。对齐掩码沿用第五轮的寄存器关系。结果 JSON 给出保守上下界及其覆盖的不同原件目标数量；逐槽 RVA 见本件第五轮同名宿主的 `s5/table-*.csv`。

在仓库根目录运行以下命令。替换原件、脚本和输出路径即可。环境为 Capstone 5.0.6、pefile 2024.8.26。

```text
python -B check-selector-bounds.py <ppexec.dll> handoff/inbox/NATIVE-346/s5 > selector-bounds.json
```
