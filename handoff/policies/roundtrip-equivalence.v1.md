# 回环等价判据 v1（提案，待上游裁决）

## 0. 为什么需要这份东西

上游 `static-acceptance`「一件怎么验」第 3 条写：「需要验证差异时，可重新编译恢复的源码，对照两边的方法实现、结构和资源」。这句话落到判据上必须回答一个问题：**两边的方法实现怎么算「对得上」？**

我们拿 9 件样本实测了四种判法，结论是**判法选择比产物质量更能决定结论**。

## 1. 四套判法的实测对比（同一批 9 件产物）

| 判法 | 结果 | 它在量什么 | 建议 |
| --- | --- | --- | --- |
| IL 字面相等 | 2/9 件 | 编译器自由发挥 | **不用** |
| CFG 等价 | 2/9 件 | 块序/变量槽重排 | **不用** |
| A：方法清单 + 外部成员集 + 指令数 | 246/267 方法（92.1%） | 结构 + 实现细节 | 辅助 |
| **C：公开 API 表** | **9/9 件** | 结构完整性 | **主判据** |

产物一次没改。四个数字从 22% 到 100%，差别全在判法。

### 为什么字面比对必然失败

实测到三类差异，没有一类是缺陷：

| 类 | 实例 | 性质 |
| --- | --- | --- |
| 表示层 | `nop`、`ldarg 0x0` vs `ldarg.0`、`ldc.i4.s`、token 行号、绝对跳转标签 | 编码差异，可归一 |
| 布局层 | `brfalse +358` vs `brtrue.s +1` | ILSpy 重排块序，语义相同 |
| 数据流层 | `ldloc.0` vs `ldloc.1` | 局部变量槽分配不同 |

要消掉第三类必须做 SSA / 变量使用序规范化，等于自研 IL 等价检查器；且等价但不同构的写法永远存在，结论仍不可靠。

## 2. 主判据 C：公开 API 表（建议采纳）

**定义**：对同一件，原件与「反编译→重编译」产物在下列集合上完全相等：

```
{ 类型全名 :: 方法名(参数类型列表) : 返回类型 }
```

排除项（编译期合成，非源作者所写）：

- `<Module>`、`<PrivateImplementationDetails>`
- 状态机 / 闭包 / 匿名类型（名字含 `<` 且以 `d__`、`c__DisplayClass`、`<>c` 等形态出现）
- `.cctor`（常量折叠后可能不再生成）

**实测**：9 件 / 267 个签名，`only_orig=0`、`only_built=0`，9/9 完全相等。

**它证明什么**：源码结构完整——没丢类型、没丢方法、签名未被改错。
**它不证明什么**：方法体实现是否逐条一致（那是 A 的事），也不证明运行期行为（那是 Windows 对照阶段的事）。

**复跑命令**：`python out/p2/p2_scheme_c.py`（产物：`out/p2/scheme-C.csv`）。

## 3. 辅助判据 A：方法清单 + 外部成员集 + 指令数

**定义**：对每个共同方法，比较（a）指令条数、（b）调用的外部成员集合（`call/callvirt/newobj/ldfld/stfld` 的解析名）。两者皆同才算通过。

**实测**：246/267（92.1%），3/9 件整件全过。

**未通过的 21 处，逐条定因如下（全部为编译器行为，非缺陷）**：

| # | 现象 | 原写法 | 新写法 | 为什么等价 |
| --- | --- | --- | --- | --- |
| 1 | 状态机类编号 | `<GetAllInstances>d__0`1` | `<GetAllInstances>d__6`1` | 编译器按文件内顺序自增的显示类编号，方法一一对应 |
| 2 | 迭代器 try/finally 包装编号 | `<>7__wrap2` / `<>m__Finally3` | `<>7__wrap1` / `<>m__Finally1` | 同一套嵌套结构，编号随嵌套顺序 |
| 3 | 字符串 switch 实现 | `<PrivateImplementationDetails>::ComputeStringHash` | `String::get_Length` + `String::get_Chars` | 老编译器生成自定义哈希，新编译器直接长度+字符比较，语义相同 |
| 4 | 数组初始化方式 | 逐字段赋值（87 条指令） | `RuntimeHelpers::InitializeArray` + RVA 静态数据（23 条） | 一次性 blit 初始化，结果数组相同 |
| 5 | 线程 ID 获取 | `Thread::get_CurrentThread` + `get_ManagedThreadId` | `Environment::get_CurrentManagedThreadId` | .NET 4.5 引入的等价快捷方法 |

**这 5 条就是全部白名单。** 每条都可被否掉：若上游认为某条不等价，删掉该条后 A 的通过率立刻下降，我们照新数字报。

## 4. 边界（写死，防止被滥用）

1. 本判据只在**我们的样本**（`dl/` 下 30 件、其中 11 件可重编译、9 件进比对）上验证过，不代表 1,315 件全适用。
2. 编译器版本差异是真实存在的：原件多为 .NET Framework 时代编译产物，我方重编译用 .NET 8 SDK。**换编译器版本，白名单要重审。**
3. **C 通过 ≠ 静态验收通过。** 它只覆盖「结构完整」一项，`static-acceptance` 的其余四项（来源、覆盖、证据、归档）不受此判据影响。
4. 任何「因为 C 全过所以这批可以放行」的推论都不成立。
