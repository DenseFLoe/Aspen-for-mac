# NATIVE-337 s61 导入目标核对

按 [覆盖证据 v1](../../standards/native-coverage-evidence.v1.md) 第 5 项核对原件位置、实际符号及调用行。在隔离目录放入固定 #445 head 的文件与同 SHA 原件，再运行：

    python -B s61-recheck.py --fixed FIXED --original ORIGINAL --output s61-recheck.json

覆盖 v1 的 SHA-256 为 27f643b9452705c4156bdb5c028f8aad2d2523fafb6853c02058d471580a34a8。基线退出 2，307／307／684／0。将 calls.csv 第 525 行的导入目标由 mfc140.dll!#2344 改为 OLEAUT32.dll!#313，并单独重算该文件指纹，覆盖 v1 仍退出 2，计数相同，未定位矛盾。期望有机械提示指出 0x106C 经过 0x4AA3 和 IAT 0x75E8 绑定至原符号，减少逐行复核。按原件字节解析 E8／E9 的目的地与导入槽，并与调用表定址行及目标核对。回归用例保留同一原件、同一真实清单和行数，只改该行的声明目标。有效行保留退出 2 及其原有未决，矛盾行应报告具体不一致。

交付的生成器 SHA-256 为 7b68263b476267db9c19c5dd2fd055b901b011a748545ef27bbe41fa9068d927。[s57](s57-verifier-notes.md) 的子目录漏站已修。新增对照中，单一候选即被返回，声称的导入目标矛盾也保留行号 525，且正常／错误两份生成 CSV 的摘要相同。缺行和重行两例也使用同一计数。生成器应逐条核对原件导入身份，分开报告缺链、竞争和符号矛盾，附实际路径、行号及原件 RVA。正常、缺行、重行和错误目标四例应分别为已匹配、缺链、歧义、目标矛盾。证据详见[实测](s61-recheck.json)。
