## 6. 实现规格（逐字；D13 算法不许改写顺序）

### 6.1 `run_batch.py` 顺序（固定）

PLAN → ［仅 `--force-analyze`：`batch_reverse.py` → `native_reverse.py`］→ assemble → `check_upload.py` → `publish.py` → 写 state → 打印 `BATCH …`。
退出码：0 全成功；1 有失败/门禁失败/断言失败/未分类异常；2 输入不可执行/环境缺失/缺产物且未给 `--force-analyze`/参数互斥；3 推送集 ≠ 审计集。

### 6.2 `--list-only` 的边界

不读 token（`_cred.py` 一次都不许调）、不发任何写请求、不写 `out/state.json`；只做 PLAN + assemble 到 `out/R3/upload/` + 门禁 + 打印 `MAP` / `DRYRUN`。

### 6.3 复用语义（默认不重跑分析）

对每件先查 ① state 里已推送且 sha 未变 ② 本地产物齐全**且** `product_sha256` 重算一致 —— **期望值取 T1 的 `out/R1/ledger-clr.csv` / T1N 的 `out/R1N/ledger-native.csv` 的 `product_sha256` 列**（r3-b I1：比对基准写死在这一列）。首轮 state 为空时该列就是基准；万一该列缺失 ⇒ 只校验产物齐全、`product_sha256` 只记录不比对，并在回执写明走了哪条。
②成立 ⇒ 不重跑，只做 assemble/gate/push（`reused`）；②不成立且 ①不成立 ⇒ 打 `ANALYZE-MISSING n=<k> items=<name…>`：`--plan-only` / `--list-only` 照常出计划；真 `--auto` 未给 `--force-analyze` ⇒ **exit 2**（绝不静默空跑）。

### 6.4 `out/state.json` 结构与增量规则

结构：`{"round":"20261120","branch":"codex/20261120-batch-review","last_commit":"<40hex>|null","items":{"<analysis_key>":{"sha256":…,"kind":…,"status":…,"product_sha256":…,"pushed":{"commit":"…"},"superseded_by":"<key>|null"}}}`
规则：① 新键 ⇒ 复用/分析 + 推送；② 键在 state 且 `pushed.commit` 非空且 sha 未变 ⇒ 跳过；③ 键在 state 但产物缺失/摘要变 ⇒ 记 `stale` + `ANALYZE-MISSING`；默认 exit 2，`--force-analyze` 才重做并再推（**不许**在默认路径悄悄重跑）；④ 同 `relative_path` 换 sha ⇒ 新键当新件、旧键标 `superseded_by` = 新键并保留历史；⑤ `--since <sha>` 与 `--state` 互斥。

### 6.5 Git Data API 九步（顺序照抄；D13）

1. `GET /git/ref/heads/main` ⇒ `main_before`。
2. `GET /git/commits/<main_before>` ⇒ `main_tree`。
3. `GET /git/ref/heads/codex/20261120-batch-review`：404 ⇒ `parent=main_before`、`cur_tree=main_tree`；200 ⇒ `parent` = `.object.sha`、`cur_tree` = 该 commit 的 `.tree.sha`。
4. `GET /git/trees/<cur_tree>?recursive=1` ⇒ 只收 type 为 blob 的条目为 `pre_paths`（**丢弃目录条目**）；断言 `truncated` 为 false；打印 `base_blob=<len(pre_paths)>`。
5. 每文件 `POST /git/blobs`（body 里 content 走 base64、encoding 为 base64）⇒ `blob_sha`；`pre_paths` 已有同路径同 blob ⇒ 跳过并 `skipped_existing+=1`。
6. 按**件**分组（58 件 + INDEX + tools = 60 组）：`POST /git/trees`（`base_tree` = `cur_tree`，每项 path / mode=100644 / type=blob / sha）⇒ `cur_tree`；再 `POST /git/commits`（message 形如 `round=20261120 item=<NAME> kind=<CLR|native|nonPE|meta|tool> files=<k>`，tree=cur_tree，parents=[cur_commit]；首组 parents=[parent]）。
7. refs 只两种：首建 `POST /git/refs`；已存在 `PATCH /git/refs/heads/codex/20261120-batch-review` 且 body 里 force 为 false；**422 不可 fast-forward ⇒ exit 1，绝不 force**。
8. 读回：`GET /git/ref/heads/<branch>` 的 `object.sha` == `cur_commit`；`GET /git/trees/<cur_tree>?recursive=1`（只收 blob、truncated 为 false）⇒ `pre_paths` ⊆ `new_paths` 且 `len(new_paths) == len(pre_paths) + 新增文件数`；`GET /git/ref/heads/main` 的 `object.sha` == `main_before`；抽 5 个文件 `GET /contents/<path>?ref=<branch>` 解 base64 后本地 sha256 一致。
9. 硬禁止（运行时断言，不是注释）：任何写 `refs/heads/main` 的请求、任何 force 为 true 的 body、任何 `DELETE /git/refs/**` ⇒ 抛错（URL 含 `/git/refs/heads/main` 且 method ∈ POST/PATCH/DELETE ⇒ 立即拒绝）。
